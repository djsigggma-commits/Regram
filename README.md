# re:gram

Android-клиент Telegram на основе **exteraless 12.10.5-beta13.1**, с переносами из
**Inugram 12.10.1-43 / md3-sliders** и **Nagram XF 1251**.

**Статус: частичная интеграция, не полное объединение. Debug-APK собирается и
проходит упаковку (arm64-v8a) с собственной Firebase-конфигурацией. Владелец
сообщил о проверке на устройстве, но протокол и логи не предоставлены.** Исходные
четыре каталога не изменены.

- Название приложения: `re:gram` во всех унаследованных локализациях.
- В интерфейсе: «Настройки re:gram → Создатели и источники» — авторы и пять источников кода. Старые каналы и ссылки из корня настроек убраны; пользовательские названия адаптированы через `tools/generate_branding.py`. Названия Java-пакетов, ключи конфигурации, ссылки совместимости, исходные переводы, документы и обязательные лицензии не переименованы: это сломало бы плагины/сохранённые настройки либо скрыло атрибуцию.
- Отдельный пакет: `app.regram.android` (не заменяет установленные исходные клиенты).
- Папка сохранения по умолчанию: `regram`.
- Сохранены исходники возможностей основы: плагины с разрешениями, оформление,
  перевод, лента, настройки чатов и другие разделы. Их наличие не означает,
  что все они заново протестированы или эквивалентны реализации Nagram XF.
  Для падений хуков сторонних плагинов нужен logcat с устройства: см.
  [диагностику плагинов](docs/INTEGRATION.md#диагностика-плагинов-с-нативными-хуками).

### Клиент, плагины, 2026-09-23…24: лаги, совместимость, debloat

Проверено `compileDebugJavaWithJavac`, `assembleDebug` (arm64-v8a, APK 114 МБ,
24.09 00:27) и `python3 -m pytest tests -q` (127 passed, 32 skipped — skipped
падают на отсутствующем локально corpus плагинов). На устройстве не проверялось.
Сборка поймала две ошибки, сделанные «на глаз»: удаление `material` (см. абзац
про debloat) и обращение к несуществующим методам `PyObject`.

Горячие пути (правки, которые обязаны быть незаметны по поведению):

- `PluginsController.rescanPlugins()` не перечитывает метаданные неизменённого
  файла: пропуск по `путь|размер|mtime` (`metadataJsonCache`), рантайм-состояние
  и прежняя ошибка загрузки сохраняются;
- эффективные разрешения плагина мемоизированы (`PluginPermissions.EFFECTIVE_CACHE`,
  сброс при любой записи прав, уровня или результата скана) — проверка стояла на
  каждом вызове из Java-гейта и каждый раз читала prefs и строила копии списков;
- `AyuFilter.isFiltered()` читает кэш до построения текста сообщения (раньше —
  после, то есть на каждую перевязку диалога и каждую позицию чата);
- `AndroidUtil.sanitizeString()` не гоняет regex `\p{Cf}`, когда нечего фильтровать
  (метод висит на каждом отображаемом тексте);
- шторка пересобирает список аккаунтов и счётчики только когда открыта
  (`DrawerContainer`): `updateInterfaces` прилетает пачками во время обработки
  апдейтов, а `refreshContents()` при открытии пересобирает всё в любом случае.

Совместимость с плагинами exteraGram сверялась не по документации, а по
исходному SDK (`../NagramXF-1251/sdk_pysrc`) — документация местами описывает
другие значения констант, чем реально исполняется. Закрыто: `HookResult` без
`__slots__` + `resultOf`/`raw`, результат хука может быть обычным `dict`
(`plugin_loader._hook_field`), `BaseHook(plugin)` и атрибуты `before_filters`/
`after_filters`, позиционные фильтры относятся к фазе декорируемого метода,
`add_menu_item` принимает dict/свой объект/позиционные аргументы, эталонное имя
`send_message_hook`, `add_file_hook`/`add_intent_hook`/`reload_settings`/
`get_plugin_config`, эталонные позиционные формы `joverride("m", ["int"])` и
`jmethod("java.lang.String", ["int"])`, `java_subclass(methods=, constructors=)`,
типы настроек и round-trip `create_settings()` ↔ `set_setting()`, очереди
`PLUGINS_QUEUE="pluginsQueue"` и другие имена тредов Telegram, `**kwargs` у
`send_*`, `pre_request_hook`/`post_request_hook` в три параметра (как в доках),
`run_on_queue(delay_ms=)`, `get_plugins_cache_dir`, ключ `formatting=` у
форматирования текста (разбор `**`/`_` и так совпадал с доками).

Со стороны Java в тот же заход: `models/PluginItemFactory` теперь спрашивает у
питоновской фабрики `attached_view`, `equals` и `content_equals` и передаёт
аргументы строки (`item.object2` → `build_view(context, divider, factory_args)`),
настройка `EditText` получает `InputFilter` по маске
(`ui/PluginSettingsActivity.createMaskFilter`, семантика — из SDK), а `mask`
сериализуется в JSON настроек (`plugin_loader`).

Не закрыто (тоже влияет на чужие плагины, точки входа указаны):

- `AppEvent.START == "app_start"`, а не `"start"` (как в доках): это значение
  реально шлёт Java, менять нельзя — но сравнение `event == "start"` у плагина
  из доков не сработает;
- из утилитного слоя не донесено: `android_utils.toast_icon`, `file_utils.pick_file`
  (нужен `startActivityForResult`-обход), `open_file_with`/`download_and_open_file`,
  `client_utils.resolvePeer`/`get_data_base`/`get_user_from_dialog_id`,
  модульные алиасы `intents.start_activity`/`share_text`, `hook_utils.jarray`;
- MVEL-бэкенд для `jMVELmethod(code=)`/`jMVELoverride(code=)` и `jclassbuilder`
  не перенесены — вызов с `code=` честно падает `NotImplementedError`;
- `is_shadow` у `SimpleSettingFactory` принять можно, но отработать он не может:
  `isShadow()` — метод общей для всех строк плагина фабрики
  (`models/PluginItemFactory.java`), а не строки; `attached_view`, `equals` и
  `content_equals` при этом вызываются (делегируются питоновской фабрике).

Debloat: `Tools/BinaryObjConverter.html` и `Tools/EmojiTextureMaker.html` перенесены
в `Tools/archive/` (не удалены: это ручные браузерные инструменты, «нет ссылок в
коде» их не объясняет); туда же — 9 битых `ic_launcher_nagram*-playstore.png`
(348 КБ) из `TMessagesProj/src/main/`: вне `res/`, в APK не попадали, ссылок ноль
(ни в коде, ни в `tools/generate_launcher_icons.py`). `.pytest_cache/` добавлен в
`.gitignore`. Остальные кандидаты из развёрнутого отчёта не подтвердились или
опасны: `com.google.android.material` нужен `M3`-индикаторам
(`CacheControlActivity:68`, `RadialProgressView:23`, `LineProgressView:21`,
`CircularProgressDrawable:16`) — пробная сборка без него падает, строка возвращена;
`androidx.swiperefreshlayout` в этом дереве не объявлен; `hiddenapibypass` нужен

### Правила, без которых работа сломается

- Патчи Inugram не накладывать: `patch -p1 --dry-run` не проходит ни для одного
  из 322, патчи написаны к стоковому 12.10.1.
- Файлы Nagram XF не копировать по факту отсутствия имени: основа часто делает
  то же самое другими классами (`AvatarCornerHelper` → `app/regram/appearance/*`).
- Совпадение имени настройки не доказывает совпадение поведения: проверять
  места использования. Так, `NekoConfig.ignoreContentRestrictions` покрывает
  только диалог ограничения, а не размытие.
- Основа может чинить тот же баг иначе: `isAdmin`/`isOwner` страховались от
  `array != null`, а не ранним `return false`. Сначала читать, потом переносить.
- Сверять API с исходным SDK (`../NagramXF-1251/sdk_pysrc`) и с Java-классами, а
  не с `plugins.exteragram.app`: документация расходится с фактическими
  значениями констант (`AppEvent`, `MenuItemType`) и обещает имена, которых в SDK
  нет вовсе (`load_class`, `get_class`, `update_menu_items`, `result_of`,
  `NotificationCenterDelegate` как «обычный python-класс» — прокси там уже был);
- Выводы агентов и собственные grep'ы проверять полными совпадениями, без
  `head`: «material не используется» выглядело доказанным, пока вывод не резали
  на 12 строках комментариев, — `assembleDebug` показал `M3`-индикаторы; «мёртвых
  `ConfigItem`» в этом дереве нет вообще (ноль совпадений и по ключу, и по полю);
- Chaquopy 17: у `com.chaquo.python.PyObject` нет `hasAttr()` и `isNone()`;
  есть `get()`, `callAttr()`, `call()`, `toJava()`. Наличие атрибута проверять
  через `get(name) != null`, отсутствие колбэка в Python — методом, который
  возвращает `None` (это уже трактуют `toJava`-фолбэки);
- Каталог не под git, удаления необратимы: спорное — в `Tools/archive/`, а не в
  корзину; зависимости снимать только вместе с прогоном `assembleDebug`;
- После каждой партии: сборка (`./tools/build.sh -Dorg.gradle.jvmargs=-Xmx10g
  :TMessagesProj:assembleDebug`, полный дайлинг не влезает в штатные 3 GiB),
  `python3 -m pytest tests -q`, `python3 tools/audit_sources.py --workspace ..`
  и запись статуса в `PORTS`. Исходные четыре каталога не трогать.

8. Отключение размытия и предупреждения для чувствительного контента (Inugram).
   Отдельно от уже имеющегося в основе «игнорировать ограничения контента»: то
   сообщение снимает только диалог ограничения.
9. Отключение подсказок хэштегов при вводе `#` в канале (Inugram).
10. Запрет скрытия темы «Общие» свайпом в списке тем форума (Inugram).
    Явные операции с выбранными темами сохраняются.

строка «Создать как супергруппу» (Inugram) — группа создаётся сразу как

## Подготовка сборки

1. Восстановите отсутствующие подмодули:

   ```sh
   ./tools/restore_submodules.sh .
   ```

   Скрипт берёт ровно те ревизии, которые закреплены gitlink-ами в исходном
   теге `exteraless v12.10.3-beta12` (FFmpeg, libvpx, dav1d, Ogg/Opus/opusfile,
   tlottie, jlatexmath, media-модуль). Архивный `.gitmodules` commit ID не
   содержит, а сам каталог не является git-репозиторием, поэтому используется
   `git init` + `git fetch` по SHA вместо `git submodule update`.

2. Соберите **вне** пути с двоеточием — `./tools/build.sh <task>`. Двоеточие в
   пути `re:gram` ломает две независимые вещи: загрузку jar-а Gradle Wrapper и
   создание venv плагином Chaquopy. Скрипт зеркально копирует дерево исходников
   в `~/projects/regram` (переопределяется через `REGRAM_BUILD_DIR`) и запускает
   там Gradle из дистрибутива (`GRADLE_BIN`); исходный каталог остаётся
   источником прав, все артефакты сборки живут в копии. Указывайте отдельный
   каталог: синхронизация использует `rsync --delete`; корень, HOME и вложенные
   в исходники каталоги запрещены. Удалённый из исходников `local.properties`
   удаляется и из сборочной копии, чтобы не переиспользовать старые ключи.

3. Установите компоненты, указанные в `build.gradle`. Ниже — набор, которым
   компиляция этого дерева подтверждена:

   | Компонент | Версия |
   | --- | --- |
   | JDK (toolchain) | 21 |
   | Gradle | 9.7.1 (из `gradle-wrapper.properties`) |
   | AGP | 9.3.1 |
   | compile SDK / platform | 37 / `android-37.0` |
   | build-tools | 36.0.0 |
   | NDK | 27.2.12479018 |
   | CMake | 3.31.6 — `sdkmanager --install 'cmake;3.31.6'` |
   | Python для Chaquopy | 3.11, путь в `CHAQUOPY_BUILD_PYTHON` |

   Версии Gradle/AGP/Maven-зависимостей больше не предполагаются недоступными:
   конфигурация проекта и загрузка плагинов проходят из сети. Системный
   `python3` другой минорной версии не подходит — Chaquopy берёт интерпретатор
   из `CHAQUOPY_BUILD_PYTHON`, иначе падает на «Couldn't find Python 3.11».

4. Скопируйте `local.properties.example` в `local.properties`. Укажите свой путь
   SDK, `TELEGRAM_APP_ID` и `TELEGRAM_APP_HASH` с https://my.telegram.org.
   Чужие Telegram API credentials не используются как fallback. Значения можно
   передать и из окружения; `REGRAM_COMPILE_CHECK=1` в `tools/build.sh`
   подставляет заведомо нерабочий pair «только компиляция» — такой APK не
   сможет войти в аккаунт.

5. Добавьте собственный `TMessagesProj/google-services.json` для
   `app.regram.android`. Конфигурация Firebase исходного клиента удалена из
   копии. Для проверки компиляции годится заглушка:

   ```sh
   python3 tools/make_placeholder_google_services.py
   ```

   Команда допускается только без настоящего `TMessagesProj/google-services.json`:
   debug-заглушка имеет более высокий приоритет и перекрыла бы его. Когда файл
   Firebase добавлен, заглушку в `src/debug` необходимо удалить; генератор
   больше не создаст её поверх настоящей конфигурации. Google Maps требует
   своего `MAPS_API_KEY`;
   иначе используйте альтернативную карту.

6. Выполните:

   ```sh
   python3 tools/check_build_env.py
   NATIVE_TARGET=arm64-v8a CHAQUOPY_BUILD_PYTHON=/path/to/python3.11 \
     ./tools/build.sh :TMessagesProj:assembleDebug
   ```

`NATIVE_TARGET=SKIP` пригоден только для проверок Java/Kotlin/ресурсов, не для
готового рабочего APK. Поддерживаются 64-битные ABI. Python движка плагинов — 3.11
по текущему Gradle-файлу (старый README основы упоминает 3.12).

Отдельно про память: в `gradle.properties` стоит `org.gradle.jvmargs=-Xmx3g`, и
для инкрементальной пересборки этого хватает, но полный прогон `dexBuilderDebug`
после изменения массово используемых классов (`ApplicationLoader`,
`NotificationCenter`) на 3 GiB падает с `D8: java.lang.OutOfMemoryError`. Лечится
явным увеличением кучи на время сборки:

```sh
./tools/build.sh -Dorg.gradle.jvmargs=-Xmx10g :TMessagesProj:assembleDebug
```

Для публичного выпуска нужны собственный ключ подписи, Firebase и проверка всех
внешних сервисов. Отдельная инструкция по ручной сборке и выпуску кандидата —
[docs/RELEASE.md](docs/RELEASE.md). `python3 tools/check_build_env.py --release`
проверяет предпосылки, а `tools/verify_release_apk.py` — пакет, ABI и подпись
готового APK. Ни одна из этих проверок не заменяет испытаний на устройстве. Без `TMessagesProj/release.keystore` и непустых `KEYSTORE_PASS`,
`ALIAS_NAME`, `ALIAS_PASS` задачи `staging`/`release` завершатся с ошибкой уже при
построении графа задач (включая `--dry-run`); `REGRAM_COMPILE_CHECK=1` и известная
пара плейсхолдеров Telegram API для них также запрещены. Наличие файлов само по
себе не заменяет проверку подписанного APK и работу приложения на устройстве.
Обновления исходного клиента не настраиваются как обновления re:gram; канал
метаданных основы сейчас отключён.

```sh
python3 -m unittest discover -s tests -p test_regram_integration.py -v
```

корпус архивов плагинов). Это проверки исходников и упаковки, **не компиляция
Android**.

Компиляция и упаковка сборочного окружения подтверждены (2026-09-22,
`NATIVE_TARGET=arm64-v8a`, см. «Подготовка сборки»):

```sh
NATIVE_TARGET=SKIP   REGRAM_COMPILE_CHECK=1 CHAQUOPY_BUILD_PYTHON=… \

NATIVE_TARGET=arm64-v8a REGRAM_COMPILE_CHECK=1 CHAQUOPY_BUILD_PYTHON=… \
  ./tools/build.sh :TMessagesProj:assembleDebug               # BUILD SUCCESSFUL
```

Результат — `regram-v12.10.3(1261)-debug.apk` (~107 МБ): пакет
`app.regram.android`, все authority в манифесте на нём же, `libtmessages.49.so`

для входа нужны свои `TELEGRAM_APP_ID`/`TELEGRAM_APP_HASH` и свой
