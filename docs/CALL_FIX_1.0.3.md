# Исправление подтверждённого вылета звонков: 1.0.3

## Диагноз

В `regram-crash.log` появился отдельный вылет `app.regram.android` от 2026-10-09 21:52:31–33. Старые записи `com.exteragram.messenger` относятся к другому приложению.

Native SIGSEGV в потоке `tgc-media`: `tgvoip::jni::DoWithJNI` → `GetEnv` → `JavaVM::GetEnv`. `sharedJVM` равен null. Адреса расшифрованы по unstripped `libtmessages.49.so` именно выпущенной 1.0.2, Build ID `c0693f565c8d579ebbf978e21f18ccae196d5f4d`.

Журнал запуска этого же процесса с телефона подтвердил первопричину:

```
Failed to register native method androidx.media3.decoder.ffmpeg.FfmpegLibrary.ffmpegGetAv1DecoderName()Ljava/lang/String;
ffmpeg_jni: JNI_OnLoad: RegisterNatives failed for FfmpegLibrary
```

Java media-зависимость в предыдущем build-каталоге была устаревшей, хотя основной код и native FFmpeg были обновлены. `JNI_OnLoad` завершался до `tgvoipOnJNILoad`, оставляя VM неинициализированной. Повторная загрузка извлечённой библиотеки также не исправляла несовместимость. Предыдущие защитные проверки звонков эту причину не устранили.

## Изменения

- Media восстановлен из Git в закреплённой beta14 ревизии `c430d207677071b1873f9f18266d55ec45722180`, а не скопирован из старого build-каталога.
- `tgvoipOnJNILoad` устанавливает `sharedJVM` до поиска классов. Modern `initWebRTC` устанавливает его при отсутствии до создания потоков/колбэков; уже установленный VM не перезаписывается.
- JNI-классы FFmpeg явно сохранены в release R8.
- `tools/verify_release_apk.py` проверяет реальные объявления методов в post-R8 DEX: классы, имена, типы параметров, результат и native-флаг. Проверяются обе FFmpeg JNI-таблицы и Java-колбэк `growOutputBuffer`. Одних ссылок на методы недостаточно. Отдельный тест сверяет спецификацию verifier с текущими C++-таблицами.
- Новый verifier отвергает выпущенный APK 1.0.2 из-за отсутствующего `ffmpegGetAv1DecoderName`.
- `tools/restore_submodules.sh` больше не считает непустой каталог без `.git` подтверждённой ревизией; такие каталоги не изменяются автоматически.
- Версия клиента `1.0.3`, versionCode `10003`; package и release-ключ сохраняются.

## Проверки

Исходники: **254 passed, 31 skipped, 27 subtests passed**. Это не проверка звонка на Android. Release APK прошёл JNI DEX-проверку, проверку подписи, совпадения сертификата предыдущего выпуска, ABI, отсутствия `debuggable` и zipalign с 16-KiB выравниванием native-библиотек. Артефакт и контрольные суммы: [BUILD_RELEASE_1.0.3.md](BUILD_RELEASE_1.0.3.md).

На телефон автоматически ничего не устанавливается. После ручного обновления необходимо проверить исходящий/входящий аудио- и видеозвонок, завершение/повторный звонок, воспроизведение голосовых и видео. Исправление конкретной причины обосновано журналом и кодом; успешный звонок и скорость запуска после исправления ещё не проверены на устройстве.
