# Проверка загрузок и жизненного цикла

Это адресное исправление найденных ошибок, не гарантия отсутствия всех багов и не измерение скорости на устройстве.

## Изменения

- `ExitFyLite.java`: HTTP-загрузка подписки вынесена из общей очереди Telegram в отдельный последовательный executor. Повторный запрос не накапливает задания; соединение закрывается в `finally`. Импорт в общий список прокси выполняется на UI-потоке.
- Обработка синхронных callback проверки прокси больше не вызывает вложенные запуски следующей проверки. Сохраняются ограничение четырёх проверок и общий таймаут. Выбор минимума сделан обычным проходом без stream; нулевой успешный пинг допустим, удалённые из списка прокси не выбираются.
- `VoskManager.java`: отмена вызывает `Call.cancel()`, сетевое чтение имеет 30-секундный таймаут простоя. Архив и staging очищаются после любой ошибки, отмены и успеха. Маркер готовности создаётся в staging до удаления старой модели; ошибка или пустой ZIP не помечает модель установленной. Убраны дублирующие операции очистки.
- Слушатели Vosk уведомляются по снимку списка: удаление слушателя во время callback и исключение одного слушателя не пропускают остальные. Завершение освобождает состояние загрузки через `finally`.
- `GitHubUpdater.java`: отмена проверяется во время копирования и непосредственно перед предложением установки, включая отмену после окончания сетевого запроса.
- `pytest.ini`: обычный запуск pytest ограничен тестами проекта, без сбора самостоятельных тестовых программ vendored native-библиотек.

Функции, пользовательские данные, плагины, JNI/рефлексивные API и зависимости не удалены.

## Проверки в этом проходе

- `python3 -m pytest -q`: **301 passed, 44 skipped, 27 subtests passed**. Пропущенные проверки не считаются подтверждением работоспособности соответствующих возможностей.
- Исполняемые Java-проверки с заглушками: 200 синхронных успешных/ошибочных ответов прокси без рекурсии, пинг 0, удаление прокси и ручная смена; Vosk ZIP traversal, пустой архив, отмена, неверная контрольная сумма, успешная установка, сохранение старой модели при ошибке скачивания/распаковки, изменение списка слушателей и исключение в callback.
- `NATIVE_TARGET=SKIP CHAQUOPY_BUILD_PYTHON=/usr/local/bin/python3.11 ./tools/build.sh --offline -Dorg.gradle.jvmargs=-Xmx10g :TMessagesProj:compileDebugJavaWithJavac`: **BUILD SUCCESSFUL**.

APK, native-сборка и тестирование на устройстве в этом проходе не выполнялись. Для дальнейшей оптимизации нужны Perfetto-трассы конкретных сценариев; эти проверки не измеряют FPS, память или расход батареи. Замена модели при ошибке файловой системы непосредственно во время rename всё ещё не является транзакционной.
