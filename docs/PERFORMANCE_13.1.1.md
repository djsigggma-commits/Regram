# Оптимизация re:gram на основе 13.1.1 — без удаления функций

Этот проход устраняет найденную повторную работу и лишние allocations.
Он **не доказывает максимальную производительность всего клиента**: замеров FPS,
батареи, cold start и Perfetto на проблемных устройствах нет. Изменение APK-размера
по сравнению с 1.4.5 также включает обновление основы 13.0.2 → 13.1.1 и не является
изолированным измерением эффекта этих оптимизаций.

Ни одна функция, настройка, локализация, тема, плагин, зависимость или JNI API
в этом проходе не удалены. Не отключались анимации, blur, сообщения, загрузки,
проверки безопасности или фоновые возможности. Состав прежних удалений upstream
при обновлении основы описан отдельно: [BASE_41526234112.md](BASE_41526234112.md).

## Устранённая лишняя работа

### Очередь плеера

- Проверка изменений сравнивает существующий список с исходным playlist в нужном
  направлении без временной копии и `Collections.reverse`.
- Если порядок и состав прежние, список не перестраивается и adapter notification
  не отправляется. При изменении заполняется существующий список с сохранением
  object identity, порядка и поведения force refresh.
- В уведомлении о play/pause текущий трек разрешается **один раз на весь набор
  видимых строк**, а не заново в каждой строке. Сохранены все три способа поиска:
  identity, dialog/message ID и fallback по `PlayerArt.key`.
- Equalizer не создаёт массив из трёх высот в каждом кадре. Скрытая view/окно
  не запрашивает следующий кадр; возвращение видимости возобновляет отрисовку,
  а временная база сбрасывается после скрытия/отсоединения.

### Текст песен

- Каждая строка держит не более одного fill-gradient. При неизменных ARGB
  повторно используется тот же Java-объект; изменение цвета/opacity пересоздаёт его.
- Progress и размеры продолжают обновлять shader matrix каждый кадр, поэтому
  подсветка не заморожена. Glow, interlude, blur, springs и автоматическая прокрутка
  не отключены. Это уменьшение Java allocations, не обещание отсутствия GPU-работы.
- Скрытые строки/окна не планируют animation invalidations; показ снова запускает
  отрисовку с корректной временной базой.

### Метки времени

- `PlaybackTimeText` хранит только два последних значения/строки на экземпляр плеера.
  Progress ticks внутри одной секунды не запускают `String.format` заново.
- Seek, смена трека, переход через час и обратный seek обновляют нужную строку.
  Сравнение с реальным текстом view сохранено: preview или внешний код не могут
  оставить устаревшую метку. Публичные API плеера не изменены.

### Карточка музыки профиля

- Анализ Palette перенесён из общей `Utilities.globalQueue` в отдельный serial executor.
  Тяжёлый анализ обложки больше не занимает очередь прочих фоновых задач Telegram.
- Собственная ARGB-копия bitmap освобождается в `finally` при успехе, исключении
  или устаревшем задании; оригинал ImageReceiver не освобождается.
- Volatile image generation позволяет пропустить анализ уже сменившейся обложки
  до запуска Palette. UI generation guard сохранён и отклоняет результат, если
  обложка сменилась уже во время анализа. Сам алгоритм Palette, разрешение копии,
  swatch selection, contrast и HSL оставлены прежними: цвета не упрощались.

### Упоминания и оформление

- `MentionAvatars.usernameFromUrl` больше не компилирует regex для каждого URL,
  не создаёт массивы от `split` и массив префиксов на каждом вызове. Проверка
  имени пользователя остаётся строго ASCII, 1–32 символа, с прежними правилами
  схем, регистров, query/fragment и отклонения приглашений/чужих доменов.
  Никакого глобального кэша peer/account/URL не добавлено.
- `MonoColor` один раз упаковывает 11 цветов текущей immutable-палитры в `Integer`.
  Nullable override API темы больше не создаёт новый объект ARGB на каждый вызов.
  Source/dark/gradient по-прежнему входят в ключ палитры; переключатели проверяются
  при обращении, disable остаётся обратимым.
- Карточки-секции настроек повторно используют конфигурацию теней, если её реальные
  цвета/alpha и density не изменились. Цвет заливки, геометрия, разные радиусы
  и default fallback продолжают обновляться. Тени не выключены.

## Что намеренно не вырезалось

R8 code/resource shrinking уже включён. `-dontoptimize`, `-dontobfuscate` и широкие
keep rules не ослаблялись: клиент поддерживает Python/Dex/Xposed-плагины, JNI и
рефлексию по именам. Они обращаются к классам/членам, которые статический shrinker
может считать недостижимыми. Удаление языков, emoji/fonts/themes, Python runtime,
Prisma grammars, native/VoIP или dynamically selected ресурсов ради размера
нарушило бы требование сохранить функциональность.

Read-only аудит предыдущего APK сохранён в
`../reports/performance-1311/apk-size-previous.json`. Он не удаляет дубликаты:
одинаковые байты под разными resource names могут быть нужны во время выполнения.

## Проверки

- Исходный suite: **457 passed, 31 skipped, 27 subtests passed**.
- Новые executable host-Java проверки: `tests/test_performance_1311.py` и
  `tests/test_profile_music_palette_lifecycle.py`.
- Parser differential test: 20 000 воспроизводимых случайных URL плюс граничные
  случаи сравниваются с прежней реализацией.
- Queue: неизменные playlist и направление проходят 10 000 запросов без
  notification; проверяются reverse, reorder, пустой список, force refresh и identity.
- Time labels: 10 000 повторов на значение возвращают тот же String; проверяются
  отрицательные/предельные int, часы, seek и независимые экземпляры.
- Gradient: 100 000 обращений с прежними цветами → один объект; изменение каждой
  из двух сторон создаёт новый. Equalizer проверяется на hide/window/detach/resume.
- Shadows: 10 000 отрисовок → две настройки shadow вместо 20 000; смена alpha или
  density обновляет обе тени, отключение карточек возвращает штатный путь.
- Реальный код profile palette worker: освобождение только собственной копии при
  успехе, ошибке Palette, stale work и fallback; generation проверяется и перед
  анализом, и после возврата на UI. Повторное событие одной картинки не копирует её.
- Реальная MonoColor-палитра: 100 000 override-вызовов возвращают тот же `Integer`;
  существующие проверки цветов, gates и смены source/темы сохранены.

Android framework заменён doubles только в host-тестах: эти счётчики подтверждают
ограничение повторной работы, **не Android rasterization или frame timing**.

Итоговый suite на версии **1.4.8.8**: **463 passed, 31 skipped,
27 subtests passed** за 80.34 секунды. Skipped corpus/device-зависимые проверки
не выдаются за пройденные. Предварительная debug/release Java/Kotlin/resources/R8

проверены. Device validation не выполнялась.

Сравнение с резервной копией: 7 изменённых Java-файлов и один новый helper;
удалённых Java/Kotlin source-файлов нет. Список и SHA-256:

## Проверка лагов на реальных устройствах

Для воспроизводимого отчёта нужны модель, Android/прошивка, частота экрана,
доступная RAM, включённые визуальные режимы/плагины и точный сценарий. Снять Perfetto
`FrameTimeline`/CPU/scheduling/GC для прокрутки диалогов и чата, клавиатуры, открытия
профиля, плеера/текста песен, очереди и возврата из background. Сравнивать на одном
устройстве с теми же данными/настройками и после прогрева; отдельно измерить cold
start, RSS/heap/GC и батарею в фоне. Не удалять настройки/данные ради «чистого» теста.

Проверить RTL, темы/source/dark/gradient, reordering/shuffle, pause/resume/seek,
часовые треки, сворачивание окна и восстановление. Плагины следует изолировать
временным отключением по одному, а не удалением: сторонний DEX может создавать
нагрузку вне изменённых Java-путей клиента.
