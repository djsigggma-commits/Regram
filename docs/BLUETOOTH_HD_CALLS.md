# HD звук звонков по Bluetooth

## Настройка

**Настройки → Настройки re:gram → Функционал re:gram → HD звук звонков по Bluetooth.**
По умолчанию выключена (`NekoConfig.regramHdBluetoothCalls`). Номер версии не менялся.

Состояние настройки и наличие выхода **Bluetooth A2DP** и встроенного микрофона
проверяются один раз в `VoIPService.onCreate`, до настройки звука. Если наушники
подключены позже, HD-режим в этом звонке не включается. Изменение переключателя
не перестраивает уже идущий звонок. Для следующего звонка условия проверяются заново.
Требуется Android 6/API 23+. Устройства только с HFP/SCO, LE Audio без A2DP,
звонки через Android ConnectionService и RTMP-трансляции не переводятся в этот режим.

## Реализация

`BluetoothMediaAudio` хранит сессию с владельцем — экземпляром службы звонка.
Не меняет глобальную громкость или пользовательскую настройку в процессе звонка.

- Android `MODE_NORMAL`, `STREAM_MUSIC`, `USAGE_MEDIA`, content type speech.
- SCO/HFP не запускается; на Android 12+ не выбирается communication device.
- Реальные `AudioTrack` получают preferred A2DP output, реальные `AudioRecord` —
  preferred встроенный микрофон и источник `MIC`. Отказ выбора микрофона считается
  ошибкой инициализации, а не разрешением незаметно использовать микрофон гарнитуры.
- Подключены Java AudioTrack/AudioRecord WebRTC `voiceengine`, которые использует
  native VoIP, и legacy `AudioTrackJNI`/`AudioRecordJNI`, включая 44.1 kHz fallback.
- Запись аудио экрана не подменяется телефонным микрофоном.
- На Android 10+ `ALLOW_CAPTURE_BY_NONE` предотвращает превращение речи звонка
  в доступный playback-capture media stream, включая обратную петлю при screen sharing.
- Штатный выбор устройства вывода работает через preferred devices. Системный
  медиамаршрут вне текущих call AudioTrack не перенастраивается под этот выбор.
- Проверки громкости в LaunchActivity и GroupCallActivity используют медиапоток.
- При отключении A2DP выбирается разговорный динамик/проводные наушники. Если
  такого выхода нет или preferred route отклонён, call AudioTrack остаётся
  приглушённым до явного выбора выхода пользователем. Автоматическое переключение
  видео на громкую связь не переопределяет этот режим.
- После окончания звонка сессия очищается; следующий обычный звонок получает
  штатные usage/stream и микрофон. RTMP остаётся на своём прежнем media-пути.

## Ограничения

**На физическом телефоне с Bluetooth-наушниками не проверено.** Android/OEM могут
игнорировать preferred device, отказывать в маршруте или менять его по собственной
аудиополитике. `setPreferredDevice` — запрос системе, а не доказательство фактического
маршрута. Реальный микрофон/выход необходимо проверить на устройстве. Нет обещания
увеличить битрейт кодека звонка: функция избегает ограничения HFP/SCO, но не меняет
кодек Telegram. A2DP может увеличить задержку; помехи, микрофон телефона и его
расстояние до пользователя влияют на качество.

Намеренного автоматического fallback на громкую связь нет, но отсутствие утечки
на конкретной прошивке при внезапном отключении наушников требует аппаратной
проверки: обработчик изменения устройств выполняется уже после системного события.

## Проверки

`tests/test_bluetooth_media_calls.py` исполняет настоящие `BluetoothMediaAudio` и
`VoipAudioManager` с Android doubles: default off, отсутствие A2DP/встроенного
микрофона, позднее подключение, API 22/23/31, media stream/usage/capture policy,
предпочтение микрофона телефона при наличии BT mic, отказ маршрутизации, ручное
переключение, disconnect/reconnect, отсутствие разговорного динамика, owner cleanup,
возврат обычного SCO-пути. Проверяется подключение к службе и обоим аудиодвижкам,
RU/EN строки и доступность переключателя. Это не Android audio-policy/device тест.

Логи Java/resources-компиляции и полного suite: `reports/bluetooth-hd-calls/`.

### Чек-лист устройства

1. Настройка выключена: обычные входящие/исходящие аудио- и видеозвонки, группы.
2. Настройка включена, A2DP подключён заранее: собеседник слышит микрофон телефона,
   звук в наушниках остаётся медиа, HFP/SCO не активен, media volume работает.
3. Звонок начат без Bluetooth, затем наушники подключены: поведение обычного звонка.
4. Изменение настройки во время звонка действует только со следующего звонка.
5. Выбор наушников/разговорного динамика/громкой связи, подключение провода,
   отключение/повторное подключение Bluetooth, планшет без разговорного динамика.
6. Mute/unmute, фон/возврат, смена сети, выход по ошибке и следующий обычный звонок.
7. Групповой звонок, screen sharing со звуком без захвата речи обратно, RTMP без изменений.
8. Android 6–11 и 12+, разные производители и наушники; подтверждение реальных
   AudioRecord/AudioTrack routed devices через dumpsys audio/audio_flinger.
