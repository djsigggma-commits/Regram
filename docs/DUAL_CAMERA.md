# Две камеры — быстрое переключение при записи кружков

## Где включить

**Настройки re:gram → Функционал re:gram → Две камеры.**
Тот же переключатель есть в **Чаты → Медиа → Камера → Дополнительные настройки**
на совместимых устройствах (раньше назывался «Бесшовное переключение»).
Оба пункта используют одну настройку; независимых конкурирующих флагов нет.

Фронтальная и основная камеры открываются одновременно при начале записи круглого
видеосообщения. При переключении выбирается уже подготовленная камера, без её
повторного открытия. В файл записывается только выбранный ракурс — это не
«картинка в картинке». **Может увеличивать расход батареи, нагрев и использование
ресурсов камеры.** Измерения расхода энергии не проводились.

Требуется выбрать **Camera2 или CameraX** в настройках типа камеры. Настройка не
переключает движок автоматически, не меняет системную камеру, видеозвонки или
отдельный dual/PiP-режим историй. Общая запись обычного прямоугольного видео в
других камерах этим переключателем не изменена.

## Хранение и совместимость

`app.regram.camera.DualCameraSettings` использует существующий глобальный ключ
`rounddual_available`. Значение по умолчанию — `false`, чтобы лишняя камера не
открывалась без явного выбора. Если ранее сохранён выбор «Бесшовное переключение»,
он сохраняется. Прежний неявный hardware-dependent default заменён явным opt-in.

Аппаратная доступность и желание пользователя разделены. Просмотр настроек на
устройстве без поддержки не перезаписывает сохранённый флаг. На таком устройстве
включить функцию с нового экрана нельзя, но можно выключить ранее сохранённый
выбор. В описании показывается предупреждение о недоступности.

## Подключение к записи

Используется уже существующий механизм `InstantCameraView`, без второй
реализации открытия/кодирования камер:

- CameraX: `CameraXSession.isRoundDualAvailable` → единая политика.
- Camera2: `DualCameraView.roundDualAvailableStatic` → та же политика.
- Политика требует сохранённого opt-in и существующих проверок
  `CameraXSession.isSeamlessSwitchingAvailable`: системная concurrent front/back
  пара, API 30+, performance/HEVC-ограничения клиента.
- На неподдерживаемых устройствах используется одиночная камера и прежний
  последовательный путь переключения.
- Существующий CameraX fallback при отказе concurrent binding сохранён.
- Существующее освобождение обоих Camera2 sessions и CameraX use cases сохранено.
- Статическая доступность dual-режима историй не менялась.

Настройка проверяется при подготовке записи; смена переключателя не отправляет
команды в уже идущую запись. Обещать абсолютное отсутствие задержки нельзя:
время переключения и возможность одновременного открытия зависят от устройства.
Реакция Camera2 на ошибки производителя в заявленной concurrent-паре осталась
штатной и требует аппаратного теста; настройка не обходит ограничения Android.

### Чек-лист устройства

1. Выключено: обычная запись и переключение, без открытия второй камеры.
2. Включено, CameraX/Camera2, фронтальная/основная как стартовая: несколько
   переключений во время кружка, непрерывный звук, ориентация и синхронизация.
3. Пауза/возобновление, отмена/отправка, фон/возврат, повторная запись: камеры
   освобождаются и не блокируют другие приложения.
4. Неподдерживаемая concurrent-пара, камера занята другим приложением, отказ HAL:
   штатная обработка ошибки без попытки обойти ограничения системы.
5. Истории/PiP, обычное видео, системная камера и видеозвонки — без изменений.
6. Сравнение температуры/энергопотребления на одном устройстве при одинаковой
   длительности и настройках записи. При заметном нагреве функцию выключить.
