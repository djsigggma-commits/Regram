# Защита загрузки истории от зависших reply/story-запросов

## Симптом и найденный риск

Пользователь сообщил о пропусках сообщений в группах, включая собственные:
пустых мест нет, повторное открытие и прокрутка не помогают, сообщения доступны
в официальном Telegram. На устройстве разработчика симптом не воспроизведён;
подключённого по ADB устройства нет. Причина конкретного случая не подтверждена.

В `MessagesController.processLoadedMessages` готовая страница истории передавалась
в UI только из callback `MediaDataController.loadReplyMessagesForMessages`.
Этот callback может ждать дополнительных сетевых запросов за цитатами и stories.
Зависание запроса или исключение внутри его обработчика удерживает всю страницу,
а не только дополнительное содержимое. Такая зависимость существует и для
истории, уже прочитанной из локальной базы.

## Изменение

- `HistoryPageDelivery` передаёт готовую страницу ровно один раз.
- При штатном завершении вспомогательной загрузки страница показывается сразу.
- Если завершения нет, через 1000 мс UI получает уже загруженные сообщения.
- Синхронное исключение во вспомогательной загрузке логируется, но не блокирует
  передачу готовой страницы.
- Поздний/повторный callback не дублирует страницу; таймер отменяется.
- Запросы цитат не отменяются; существующий `replyMessagesDidLoad` продолжает
  обновлять цитаты после показа истории.
- Метаданные страницы, cache flag, load index, счётчики и порядок сообщений
  не изменены. Путь секретных чатов и quick replies сохранён.
- База, правила фильтров и пользовательские данные не очищаются.

Это защита конкретного подтверждённого пути отказа, а не доказательство, что
все возможные причины пропусков истории устранены.

## Проверки

`tests/test_history_page_delivery.py`: 3 host-Java/integration проверки.
Проверяются быстрый callback, отсутствующий callback, таймер, поздние/повторные
callback, исключение, независимые страницы, неизменность аргументов уведомления,
ветка без обработки, secret/quick-reply ветки. Integration-проверка исполняет
извлечённый реальный участок `MessagesController`, а не его переписанную модель;
Android scheduler, загрузчик цитат и NotificationCenter заменены doubles.

JDK 21, полный suite: **489 passed, 31 skipped, 27 subtests passed**.
Логи сборки и тестов: `reports/history-page-fix/`.

## Проверка на устройстве

Установить кандидат поверх текущего re:gram без удаления данных. Открыть ту же
группу и сравнить конкретный пропущенный участок с официальным Telegram.
Проверить старые/новые страницы, собственные сообщения, ответы на сообщения
из других групп, stories, открытие цитаты, отсутствие дублей после ожидания,
плохую сеть и офлайн-историю. Если пропуски сохраняются, нужны runtime-логи
загрузки конкретного участка: эта правка не восстанавливает повреждённые
метаданные cache holes и не отключает явно настроенные фильтры.
