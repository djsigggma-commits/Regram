# Встроенный Termux Bridge

Перенос `termux_bridge.plugin` 1.0.0 от **@S1mclick** непосредственно в re:gram.
Исходный файл: `/home/atb/Загрузки/Telegram Desktop/termux_bridge.plugin`,
SHA-256 `7d630c354a5d39d0e8da28ed1fbb1788c807cb2b533eba7822d75b6e3984bd9c`.
Закрытых DEX/нативных компонентов в этом файле нет; явная лицензия/ссылка на репозиторий в нём не указана.
Плагин не исполнялся при переносе: строки CLI/установщика/документации извлечены через AST.
В APK не добавляется `.plugin`, не устанавливается BasePlugin и не загружается DEX.

## Подключение

**Настройки → openExtera → Other → Termux Bridge**:

1. «Подключить Termux»; подтвердить включение локального сервера.
2. Скопировать команду в Termux. Она устанавливает Python/curl и локальную утилиту `tgb`.
3. Запустить `tgb`, затем `status`, `show Привет --timeout 5` или `docs`.
4. Для Java и команды `tg` отдельно разрешить выполнение Python/Java внутри клиента.
5. Для ИИ указать HTTPS endpoint, API-ключ и модель. По умолчанию Groq / `openai/gpt-oss-120b`, как в исходнике. До явного запроса обращения к ИИ нет.

Примеры в Termux:

```python
from tgbridge import Panel, show, notify, wait, java

show('Привет', pos='top', timeout=5)
p = Panel('Пульт', pos='bottom_end')
p.button('Уведомление', lambda: notify('Нажато', 'success'))
p.toggle('Переключатель', lambda value: show(value))
p.slider('Число', 0, 100, 50, lambda value: show(value))
p.input('Текст', lambda value: show(value))
p.show()
wait()  # в отдельном скрипте, чтобы не потерять подписку на события
```

`print`, shell-команды, `run`, `py`, `pipe`, `btn`, постоянное пространство имён оболочки,
`ai`, подтверждение ИИ-кода и обратные вызовы выполняются в **Termux**, как в оригинале.
`tg`/`tgrun` исполняют Python **в процессе re:gram** только после отдельного разрешения.
API-ключ не копируется в утилиту Termux.

## Нативная реализация

- `app/regram/termux/TermuxBridge.java`: localhost TCP/JSON, подключение, аутентификация,
  подписки, ИИ HTTPS-запросы, явный exec, жизненный цикл.
- `TermuxWire.java`: ограниченное чтение строк, constant-time сравнение токенов,
  одноразовое подключение по монотонным часам.
- `TermuxUi.java`: текстовые оверлеи, перетаскиваемый шарик и панели с text/button/toggle/
  slider/input/row, изменение элементов, закрытие и очистка владельца. Настоящие Android listeners.
- `TermuxJava.java`: **явные** RPC-вызовы публичных методов/конструкторов/полей Java,
  типизированные аргументы/массивы, объекты и интерфейсные слушатели. Reflection здесь
  обслуживает команды пользователя, не меняет и не перехватывает методы Telegram.
  `java.lang.reflect.Proxy` создаёт новый объект-слушатель, а не хук существующего метода.
- `TermuxBridgeActivity.java`: встроенные настройки на русском и английском.
- `assets/regram/termux_*.txt`: адаптированный CLI, установщик и документация ИИ.
- `src/main/python/regram_termux_exec.py`: маленький штатный исполнитель **пользовательского**
  Python-кода; не Python-плагин и не реализация сервера/UI. Используется уже поставляемый CPython/Chaquopy.
  При этой операции не импортируется `plugin_loader` и не требуется включать менеджер плагинов.
  Старт CPython согласован с общим движком через `synchronized (Python.class)`;
  обычные плагины и их настройки сохраняются.

Команды: `ping`, `diag`, `subscribe`, `show`, `append`, `clear`, `ball`, `notify`, `clip`,
`panel`, `set`, `close`, `exec`, `ai`, `ai_docs`, `j_info`, `j_cls`, `j_activity`, `j_new`,
`j_call`, `j_get`, `j_set`, `j_str`, `j_list`, `j_listener`, `j_add_view`, `j_remove_view`.

## Отличия и защита

- Сервер и exec **выключены по умолчанию**. Отдельные предупреждения объясняют полный
  доступ доверенного кода ко всем аккаунтам и данным клиента. Это не песочница.
- Только `127.0.0.1`; сам по себе localhost **не изолирует** другие Android-приложения.
  RPC требует случайный 192-битный токен. Ссылка установки содержит отдельный секрет,
  действует один раз/5 минут; открытого `/i` с выдачей токена больше нет.
- Не передавайте ссылку подключения, содержимое буфера обмена с ней и файл
  `~/.tgbridge/tgbridge.py`. Установщик выставляет каталог `0700`, скрипт `0600`.
- Токен/API-ключ находятся в закрытых `regram_termux` preferences, **не зашифрованы
  отдельно**. Эти preferences исключены из Android full backup и device transfer,
  не добавлены в экспорт `.extera`. Старые настройки плагина не импортируются автоматически.
- «Отозвать подключения / обновить токен» закрывает сокеты, удаляет UI и объекты;
  требуется повторное подключение. Изменение разрешения exec тоже сбрасывает сессии.
- При показе код-пароля подключения и оверлеи очищаются, запросы заблокированы до разблокировки.
  При уничтожении окна сервер остановлен. При возврате в живое окно включённый сервер запускается.
  Отдельный foreground service, wakelock и разрешение системного оверлея не добавлены.
- Отключение сервера **не может безопасно прервать уже запущенный произвольный Python/Java**,
  отменить его действия или очистить созданные им самостоятельно потоки/объекты.
  Python может обращаться ко всему интерпретатору. Долгий Java-вызов может заблокировать UI.
- Есть пределы: 8 соединений, JSON-строка 1 MiB, 64 исходящих сообщения на соединение,
  32 панели, 128 элементов на панель, 128 прикреплённых Java-view, 4096 Java handles,
  глубина элементов 4. Запись событий в сокет не блокирует UI. Переполнение закрывает соединение.
- После потери подписки удаляются панели/view без `keep=True`; Java handles владельца
  освобождаются. Обычный RPC без подписки освобождает handles при закрытии последнего соединения.
  `keep=True` действует только до остановки/блокировки/уничтожения окна, не сохраняется на диск.
- Просроченная, ещё **не начатая** UI-команда отменяется и не выполнится после ответа об ошибке.
  После обрыва ответа CLI не повторяет потенциально уже исполненную команду.
- ИИ отправляет документацию, пользовательские инструкции, запрос и до 12 сообщений
  истории tgb выбранному HTTPS endpoint; сообщения Telegram автоматически не собираются.
  Перенаправления отключены, ключ не отправляется другой конечной точке автоматически.
  Перед выполнением CLI показывает **весь** сгенерированный код и ждёт `y`/`да`.
- Exec создаёт новое пространство имён на каждый запрос (постоянное — только в tgb).
  Захватывается обычный `print`, без глобальной подмены `sys.stdout` общего Python-движка;
  прямые записи в `sys.stdout` не возвращаются в `output`. Размер вывода — до 64 KiB.
- Java RPC поддерживает публичные API, оставшиеся в APK, и явные типы для перегрузок.
  Это не полная копия разрешения перегрузок Chaquopy: при неоднозначности используйте
  `java.i/f/d/l/b`, типизированный массив; скрытые Android API и отсутствующие после R8
  методы не гарантируются. Слушатели доступны для интерфейсов, не для наследования классов.
- Поля/ползунки ограничены размером экрана; большие панели прокручиваются.
  Внешний вид не побайтная копия исходного плагина.

Не устанавливайте исходный плагин одновременно с нативной функцией: возможен конфликт порта.
Существующую пользовательскую установку плагина автоматически не удаляем.

## Проверки и статус поставки

`tests/test_termux_bridge.py` проверяет реальный Java transport на loopback, токены,
одноразовую/просроченную выдачу установщика, exec gate, владельцев handles, Java casts/
listeners, отмену запоздалых UI задач, блокировку, отзыв и остановку. Проверяются CLI,
подтверждение ИИ-кода и Python helper без перенаправления общего stdout.

`tests/test_termux_ui.py` исполняет **настоящий TermuxUi** с небольшими host Android stubs:
текст/обновление/таймауты, шарик, элементы панелей и события, тихие программные обновления,
отключение дочерних controls, изоляция панелей, `keep`, пределы и очистка.
Это **не** проверка отрисовки или реальной работы Android/Termux на телефоне.

Результат проверки текущих исходников:

- Общий `pytest -q`: **327 passed, 31 skipped, 27 subtests passed**.
- `compileDebugJavaWithJavac`, `compileDebugKotlin`, `processReleaseResources`: **BUILD SUCCESSFUL**.
- Логи: `/tmp/regram-termux-full-tests.log`, `/tmp/regram-termux-compile-final.log`.
- В Gradle остаются предупреждения об устаревших возможностях и некоторых старых
  ресурсах без default value; успешная компиляция не заменяет device-проверку.

Изменения предназначены для следующей сборки. Версия/старый APK 1.1.6.3 не изменены;
новый APK с Termux Bridge пока не создан. Нужны device-проверки Termux → re:gram,
CPython/Chaquopy callbacks, фонового режима, код-пароля и выбранного API ИИ.
