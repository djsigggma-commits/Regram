# Проверка вылета звонков и долгого запуска

**Обновление 1.0.3:** журнал телефона подтвердил несовместимость Java/native FFmpeg и неинициализированный `sharedJVM`. Причина и целевое исправление описаны в [CALL_FIX_1.0.3.md](CALL_FIX_1.0.3.md); приведённые ниже изменения 1.0.2 эту причину не устранили.

Изменения в исходниках 1.0.2 после сообщения о падении при ответе собеседника и запуске до 15 секунд. **Причина конкретного падения ещё не подтверждена logcat; работа исправлений на телефоне не проверена.**

## Звонки

- Версия движка выбирается из согласованных сервером версий, которые действительно есть в native-библиотеке текущего ABI. Порядок предпочтений сервера сохранён; несовместимая версия завершает звонок ошибкой, а не подменяет протокол произвольно.
- JNI больше не разыменовывает `nullptr`, если `Meta::Create` не смог создать движок. Временный holder освобождается автоматически, Java проверяет нулевой handle.
- Добавлены проверки 256-байтного ключа и 16-байтного peer tag перед `memcpy`. Endpoint инициализируется нулевыми значениями. При pending JNI exception создание прекращается.
- Инициализация WebRTC сериализована mutex; флаг готовности выставляется после создания JNI class refs и method ID, а не до них.
- Исправлена арифметика указателя в сообщении об неизвестном data-saving режиме.
- Короткие/отсутствующие массивы амплитуды и callback от уже завершённого сервиса не обновляют интерфейс нового звонка.
- Ошибки связывания native-кода (`LinkageError`) обрабатываются в запуске личного звонка. Это **не** перехватывает SIGSEGV/SIGABRT внутри произвольного native-кода.

## Запуск

- Конфигурации всех слотов аккаунтов по-прежнему читаются, но сетевые, контактные и download-контроллеры создаются только для выбранного и авторизованных аккаунтов. Изменение сети не создаёт контроллеры пустых слотов. Рабочие аккаунты не отключены.
- Инициализация плагинов поставлена в main-looper после возврата из базового запуска. Убрано принудительное получение GIL главным потоком во время старта Python; существующее ленивое закрепление thread state при использовании хуков осталось.
- Задачи старта Python повторно проверяют состояние после попадания в executor, чтобы параллельные запросы не повторяли уже выполненную инициализацию.
- Fallback-копия `libtmessages` привязана к размеру и времени изменения установленного APK. Постоянный `LIB_VERSION=49` больше не позволяет случайно повторно загрузить копию библиотеки от предыдущего APK. Обычный `System.loadLibrary` остаётся первым вариантом.
- Fallback-распаковка использует буфер 64 KiB без `Thread.yield()` на каждые 4 KiB; неудачная загрузка больше не возвращает успешный результат.
- При включённых логах выводится длительность базовой инициализации (`re:gram base init took ... ms`). Это не время до первого отображённого кадра.

## Проверки исходников

- С JDK 17 в PATH: `python3 -m pytest tests -q` — **246 passed, 32 skipped, 27 subtests passed**. Без javac два Java-теста пропускаются: 244 passed, 34 skipped.
- Проверен синтаксис Java и arm64 JNI translation unit через NDK Clang (`-fsyntax-only` с include/generated dependencies из существующего дерева сборки `/home/atb/projects/regram`). Это не сборка/линковка нового APK.
- Новый Java-тест выполняет настоящий метод выбора версии с подставленным списком доступных движков, включая неподдерживаемую первую версию, null и пустой список.
- Позднее выполнена release-сборка с пересборкой native-библиотеки и Java из одного дерева; APK подписан прежним release-ключом, `debuggable` отключён. На телефон APK не установлен и звонки не проверены. Артефакт и проверки: [BUILD_RELEASE_1.0.2.md](BUILD_RELEASE_1.0.2.md).
- Резервная копия до изменений: `../Regram-before-call-startup-fix.tar.gz`.

## Нужные данные с телефона

Сообщите модель, Android, версию/источник установленного APK, обычный или видеозвонок, входящий или исходящий, включённые плагины. На этом компьютере сейчас нет подключённого adb-устройства.

Запустите запись, затем воспроизведите звонок до вылета и остановите запись Ctrl+C:

```sh
adb logcat -b main -b system -b crash -v threadtime > regram-call.log
```

Для уже произошедшего падения:

```sh
adb logcat -b crash -d > regram-crash.log
```

Перед отправкой удалите личные данные из журналов. Для сравнения временно выключите плагины в настройках (не удаляя их и не очищая данные приложения), повторите холодный старт и звонок. После нового APK проверьте входящий/исходящий аудио- и видеозвонок, повторный звонок после завершения, Bluetooth/динамик, запуск с несколькими аккаунтами и сохранение push у всех авторизованных аккаунтов.
