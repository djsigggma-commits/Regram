# Встроенные аватары упоминаний

Нативная реализация обновлена по функциям MentionAvatars DEX **1.1.3** от @limeplug. Исходники: [limezsh/mentionavsdex](https://gitlab.com/limezsh/mentionavsdex), commit `756380a5f32ebe4b1bc8f68beb503c6ef31c2ddc`, лицензия GNU GPL v3. Предоставленный `mention_avatarsDEX (3).plugin` побайтно совпадает с файлом этого commit (SHA-256 `407643933f55534715f4746920986803a0689ca2a89f85a41e55ace1e9739dd3`). Плагин изучен как текст, не исполнялся. DEX плагина не включается в APK; хуки и загрузка плагина не используются. Существующий движок остальных плагинов сохранён.

## Включение

**re:gram → Оформление → MonoColor, AllLeft и упоминания → MentionAvatars**.

Перед включением отключите исходный плагин `mention_avatars`. Его настройки не импортируются, сам плагин и данные не удаляются.

- Аватары рядом с упоминаниями: по умолчанию выключены.
- Расположение: перед / после ника / **вместо @**; по умолчанию перед. Старые значения 0/1 сохраняют смысл, новое значение — 2.
- Размер: 14 / 16 / 18 dp; по умолчанию 16.
- Каналы и группы: включены по умолчанию.
- Боты: включены по умолчанию.

Все пять параметров сохраняются в NekoConfig. Поддерживаются `@username`, упоминания пользователя по ID и ссылки `t.me`, `telegram.me`, `tg://resolve?domain=` в тексте сообщений и подписях к медиа. Пользователь/чат должен быть уже известен текущему аккаунту; неизвестное упоминание остаётся обычной ссылкой. Дополнительные запросы разрешения username и поиск по другим аккаунтам не выполняются. Изображения аватаров загружаются стандартным ImageReceiver только при подключении ячейки к окну.

## Что изменилось относительно реализации 1.1.1

- Добавлен третий режим из плагина 1.1.3: аватар заменяет только отрисовку символа `@`, ширина равна размеру аватара, без дополнительного промежутка. Буквы username остаются обычным текстом и могут переноситься; буквальный `@` сохранён для копирования и редактирования.
- Если диапазон ссылки начинается сразу после `@`, декорируется предыдущий символ. Если `@` нет (упоминание по ID или ссылка с произвольной подписью), как в плагине используется расположение перед подписью. Спойлер/код/чужой ReplacementSpan на самом `@` не замещаются.
- Подпись настроек использует отдельные два бита для каждого селектора: третий режим не конфликтует с размером. Смена режима, размера и фильтров обновляет обе текстовые проекции.
- Новый EditHook исходного плагина исправляет последствия вставки NBSP/пробелов. В нативной реализации символы вообще не вставляются; существующий `ChatActivityEnterView.applyMessageEntities()` снимает спаны перед восстановлением сущностей. Дополнительный хук или дублирующая очистка не нужны.
- Сохранены более строгие ограничения клиента: поиск только в текущем аккаунте, строгая проверка URL, блокировка любых пересечений со спойлерами/кодом. Cross-account fallback и общий пул спанов плагина намеренно не переносились: они не нужны для новой опции и могут раскрывать сведения другого аккаунта/удерживать View.

## Код и ограничения

- `app/regram/chats/MentionAvatars.java`: обработка URLSpan, фильтры, локальный поиск, максимум 40 аватаров на текст, подписи конфигурации.
- `app/regram/chats/MentionAvatarSpan.java`: обычный нативный AvatarSpan; режим замены скрывает отрисовку только `@`, остальные режимы добавляют ширину и рисуют исходный краевой графемный/словесный фрагмент. Длинная ссылка не превращается в один неразрывный replacement span. Для коротких не-ASCII краевых слов сохраняется цельное рисование.
- `MessageObject`: обработка после entity parsing и до layout; отдельные подписи настроек для текста и caption предотвращают устаревание второй проекции при частичной регенерации.
- `ChatMessageCell`: привязка/освобождение родителя при layout, attach, detach и повторном использовании ячейки. Ячейка хранит собственный ограниченный список привязанных спанов, поэтому освобождает и старые спаны после пересоздания текста; освобождение проверяет владельца родителя.
- URLSpan и его исходный полный диапазон сохраняются: нажатие обрабатывается обычным клиентом. Строка, messageOwner, позиции сущностей, копирование и реальная принадлежность сообщения не меняются.
- Спойлеры, моноширинный код и диапазоны с другими ReplacementSpan не декорируются. Проверяются как отдельные TextStyleSpan, так и style flags самого URLSpan.
- Общего статического пула спанов/ссылок на View нет. При выключении старые спаны снимаются, обработка caption и текстовый layout обновляются.

Автоматические тесты выполняют реальный Java helper с минимальными API-заглушками: URL, account isolation, фильтры, диапазоны, повторная обработка, отключение, ограничение количества и сохранение недекорированного остатка длинных ссылок на уровне границ спанов. Дополнительный тест исполняет настоящий MentionAvatarSpan с графическими заглушками: ширину, метрики и порядок рисования до/после и отсутствие отрисовки `@` в режиме замены для всех трёх размеров. Проверены уникальность всех 36 включённых конфигураций, неверные индексы, переходы между режимами, отключение, сохранение полного диапазона URLSpan и обработка `@` за границей сущности. Статическая проверка подтверждает существующую очистку спанов редактором. Они не заменяют Android StaticLayout и отрисовку на устройстве.
